## Dependency & Upgrade Constraints

Hard-won constraints from past upgrades — read before touching these dependencies.

- **Sanity is on `6.x` (`sanity@^6.18`, `@sanity/ui@4`, `@sanity/icons@5`, `@sanity/client@8`).** We were pinned to v5 because the v6 rolldown CLI (`@sanity/cli@7`) broke `sanity schema extract`; `@sanity/cli@8` (sanity ≥6.17) fixed it, and the `web/sanity.cli.ts` `vite` hook that patched the v5 worker is gone (extract output is identical without it). v6 gotchas: `@sanity/ui@4` renamed `space` → `gap` and moved `Popover`/`Menu*`/`Toast`/`Tooltip` to subpaths (`@sanity/ui/popover`, …); `@sanity/icons@5` dropped many root exports — import them from `@sanity/icons/<Name>` (e.g. `@sanity/icons/ThLarge`). **Both removals are typed `never`, so `tsc` passes and only `next build` fails** — always run a build after touching Sanity UI/icon imports. `ts:extract` needs `--force` (the v8 CLI won't overwrite `schema.json`), and typegen config lives in `web/sanity.cli.ts` `typegen` (the separate `sanity-typegen.json` is deprecated). Singletons use Sanity's **native singletons API, which is still beta** (see `studio/AGENTS.md` → "Singletons"). Check the changelog for it on every Sanity bump. After any Sanity bump run `pnpm ts:typegen`, `pnpm typecheck` **and** `pnpm build`, then open `/admin` and the standalone Studio.
- **`@c15t/nextjs` is on `v3`** (cookie consent), with `@c15t/react` on the same version for the `offline()` provider transport (the `offline` that `@c15t/nextjs` exports is `c15t.config.ts` data, not a transport). Everything lives in the `"use client"` module `web/src/ui/cookie-consent/consent-manager.tsx`, loaded lazily: `ConsentProvider` in `offline()` mode (choices stay in the visitor's `c15t` cookie, there is no consent backend), `ConsentTheme` for the tokens from `theme.ts`, then `ConsentBanner` and `ConsentDialog` (both `hideBranding`). Google Tag Manager is a c15t script there (`@c15t/integrations/google-tag-manager`, `loadMode: "after-consent"`): it is what puts Measurement and Marketing in the dialog, and nothing reaches Google before consent. Any other third-party tag goes in the same `scripts` array; a tag added outside it loads without consent and is missing from the dialog. Don't import a c15t stylesheet: v3 components inject their own rules, so the CSS ships with the lazy chunk, and with `inlineCss` a global import would put it into every page's HTML.
- **`pnpm-workspace.yaml` has an `overrides` block** (pnpm 12 no longer reads the `pnpm` field in `package.json`, so it must stay there) pinning transitive deps to patched versions (Dependabot High CVEs). Don't remove it. Overrides stay within the patched package's current major (e.g. `undici@6`/`undici@7` keyed separately); `uuid` (<11) and `esbuild` (vite 7 pins 0.27) are deliberately left unpatched because the fix is a major bump (moderate/low, CLI/dev-server only).
